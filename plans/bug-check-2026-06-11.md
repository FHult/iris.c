## P2-1 — style bundle tmp files match the `*.npz` glob

`style_precompute.py:140`: `tmp = dst.with_suffix(".tmp.npz")` — a crash or
`pause --free-gpu` kill mid-write leaves `shard.tmp.npz`, which **matches every
`*.npz` glob** in the chain:

- `style_neighbors.load_cache` loads it → truncated-zip exception → style step
  exits nonzero → iteration silently falls back to legacy cross-ref.
- The manifest's `shard_count`/`record_count` include it.
- If the kill lands between `savez` and `rename`, the complete-but-unrenamed
  tmp can be **published to cold** (orchestrator publish globs `*.npz`),
  permanently polluting `v1_csd` with a junk-named duplicate bundle.

Fix: use the `precompute_all._atomic_savez` pattern (`savez` to `X.tmp` →
np writes `X.tmp.npz` → `os.replace` to `X.npz`, unlink on failure), and have
`load_cache` / report / publish skip names containing `.tmp.` defensively.

## P2-2 — cold publish never upgrades a stale bundle (monotonic growth broken)

`orchestrator.py:3332-3336`: publish copies a bundle only `if not
_dst.exists()`. When an iteration **upgrades** a bundle (cold had 50 keys,
subsample is now 200 → `bundle_complete` correctly re-encodes 200), the bigger
bundle is never written back — cold stays at 50 forever and **every future
iteration that stages this shard re-encodes it**. The DP-2c "published npz are
a permanent prefix; raising N encodes only the complement" contract holds at
the skip check but breaks at publish.

Fix: overwrite when the local bundle has strictly more keys than the cold one
(`len(np.load(local).files) > len(np.load(cold).files)`; key-count read is
header-only and cheap).

Related doc nit: BACKLOG/plan language says a fuller pass "encodes only the
complement" — the code re-encodes the whole prefix (no merge with the existing
bundle). Behavior is correct, the description oversells it.

## M-1 — VAL cond_gap evaluates ONLINE weights; the promoted artifact is EMA

`train_ip_adapter.py:2417` runs the final held-out paired eval with the live
`adapter` (online weights), but the artifact the flywheel promotes/champions is
`best.safetensors` = **EMA** params (written at :2389). flywheel_lib then makes
this VAL gap supersede everything for champion selection — so iterations are
ranked by a model that is not the one being shipped. At 1000-step from-scratch
iterations EMA lag is material (we track `ema_drift` precisely because it is).

Fix: swap EMA params into the adapter for the final eval (and restore), or
print a second `VAL-EMA …` line and have `collect_metrics_from_log` prefer it.

## M-2 — doctor flags the DP-1 stop-early as CRITICAL for 48 h

`pipeline_doctor.py` proxy section: log fresh + no `EXIT_CODE` + no process →
CRITICAL "training died without an exit marker". The **morning checklist's
sanctioned stop-early** (`tmux kill-session` + `pkill`) produces exactly this
state, so the doctor will cry crash right after the user follows instructions —
today.

Fix (either): treat a `proxy_vae_eval.json` newer than the log's mtime as an
intentional stop (downgrade to INFO "stopped early, verdict available"); or
make the checklist append `echo "EXIT_CODE=130" >> /Volumes/2TBSSD/logs/proxy_vae_train.log`.

## M-3 — subsample "first N valid" rules diverge between encoders

- `precompute_all.iter_shard`: valid = has **img AND txt** members (counts even
  if the JPEG later fails to decode).
- `style_precompute.encode_shard`: valid = **decodable image** (no caption
  requirement; undecodable excluded).

On shards with missing captions or corrupt images the two N-prefixes diverge:
style-neighbor records lack SigLIP (per-sample fail-open → quietly lower
`style_pair_pct`) and SigLIP'd records lack style embeddings (can't pair).
Fix: align style_precompute to require a txt/caption sibling and count a record
toward N before attempting decode (mirror iter_shard exactly).

## M-4 — loader picks style neighbors with no cosine floor

`dataset.py:518`: `rng.choice(_nbrs[:5])` ignores the stored `neighbor_cos`.
For style-isolated records (the ~56 % that are not pair_rich at tau 0.6) the
"neighbor" may sit at cos 0.2 — effectively an arbitrary pairing, yet it is
counted as `style_pair` in telemetry, overstating true same-style coverage and
re-introducing (diluted) the reference-ignoring gradient run5 exists to kill.
Fix: load `neighbor_cos` too and require cos ≥ tau (e.g. 0.6); below it, fall
back to legacy for that sample so `style_pair_pct` stays honest.

## M-5 — VAL gap supersedes the train gap with no n_pairs floor

`flywheel_lib.collect_metrics_from_log`: any parsed `VAL … [n=1]` replaces
`cond_gap` for champion selection/attribution. With thin val SigLIP coverage a
near-meaningless 1-pair gap silently outranks a 1000-step train statistic.
Fix: only supersede when `val_n_pairs >= 16` (keep the `val_*` fields always).

## M-6 — config_schema doesn't know the flywheel keys

`config_schema.py` validates top-level sections and `flywheel_health` nested
keys, but **not `flywheel.*`** — `style_paring: true` or
`precompute_subsample_pershard:` would be silently ignored, and the SREF chain
is fail-open by design, so nothing downstream would complain either: the run
would quietly execute as run4. Add a `flywheel` entry to `NESTED_KNOWN`
(the key set is bounded and already enumerated in run5's config).

## L (minor)

- **L-1** `style_neighbors.py`: if a record has fewer than k eligible
  candidates, top-k slots carry the −2 sentinel → arbitrary indices stored as
  "neighbors"; also `argpartition(-cos, k)` raises outright when n ≤ k (tiny
  smoke caches). Drop entries with cos ≤ −1 when writing rows and clamp
  `k = min(k, n-1)`. The nn5 acceptance ratio also averages sentinel slots in,
  making the reported ratio slightly pessimistic.
- **L-2** `dataset.py:549`: `r_arr` is all-or-nothing per batch — one neighbor
  miss drops style refs for the whole batch. Moot at the current
  `batch_size: 1`; revisit if Stage 2/3 raise batch size.
- **L-3** `style_pair_pct` parsed by flywheel_lib is the LAST log window only
  (counters reset per window) — a tail sample, not the iteration mean.
- **L-4** `iris_kernels.c` OOM comment says "log once" but logs per call —
  comment or behavior, pick one.
- **L-5** `style_shard_report.py` hard-codes the 0.95 dedup band that
  `style_neighbors.py` exposes as `--dedup-cos`.
- **L-6** `sref_eval.py` stem matching: a ref dir with `x.jpg` and `x.png`
  keeps whichever iterates last; deterministic but arbitrary.
